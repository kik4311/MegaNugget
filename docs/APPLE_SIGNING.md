# Экспериментальная подпись через Apple Account

## Что добавлено

В Desktop → App Installer есть режим **«Подписать MegaNugget через Apple Account»**.
Это реальная интеграция Rust-библиотеки [isideload](https://github.com/nab138/isideload),
а не фиктивная генерация сертификата или обход Code Signing.
Зафиксирована ревизия `326e56229d0727cb6e7b34c8cf03e37e2cd3e17d` (0.5.2).
Она использует неофициальные developer/auth endpoints Apple и apple-codesign-quick.
Apple может изменить эти протоколы или отклонить авторизацию/provisioning.
Не утверждается, что Apple официально поддерживает этот Linux workflow.

**Сейчас поддерживается только исходный `org.meganugget.ios`, без frameworks,
PlugIns и dylib.** Это наш простой исследовательский клиент. GoldenNugget с
минимальной iOS 26.0 не станет совместимым с iOS 15 после переподписи.

## Как использовать

1. Запустите обновлённый Desktop; старый бинарник из прошлого этапа этого режима не имеет.
2. Разблокируйте iPhone, подтвердите доверие, выполните «Проверить USB» и выберите устройство.
3. App Installer → режим Apple Account → выберите `MegaNugget-UNSIGNED.ipa`.
4. Введите Apple Account и обычный пароль аккаунта **в локальном приложении**,
   не в чате, терминальной команде или GitHub Secret. App-specific password может
   не подходить для этого протокола; MegaNugget не обещает его поддержку.
5. Прочитайте согласие, отметьте checkbox и подтвердите отдельный системный диалог.
6. Введите код 2FA от Apple. Основной сценарий — доверенное устройство;
   выбор/повторная отправка SMS в интерфейсе пока не реализованы.
7. Если команд несколько, выберите Team. Дождитесь результата подписи.
8. При успехе сохраните подписанный IPA или отдельно нажмите «Установить на iPhone».
   Только после нового подтверждения запускается существующий installer.

Никаких Apple Account по умолчанию, фиктивных профилей и скрытой подписи нет.
Неподписанный объект имеет отдельный Rust-тип и не принимается обычным installer.

## Явные побочные эффекты

- В аккаунте Apple могут создаваться development certificate, App ID, app group,
  provisioning profile, а UDID выбранного устройства регистрируется у Apple.
- isideload добавляет Team ID к Bundle ID; переподписанное приложение имеет иной ID.
- При исчерпании лимита сертификатов возвращается ошибка: **никакого автоматического
  отзыва чужих/существующих сертификатов** и отключения защит нет.
- Бесплатное provisioning обычно действует 7 дней; действуют лимиты Apple.
- Отмена/таймаут не откатывают регистрацию устройства и ресурсы аккаунта.
- Подпись не предоставляет jailbreak, kernel access и не снижает MinimumOSVersion.

## Сеть и хранение

Нет запросов при запуске/открытии формы. Только после системного подтверждения:

- авторизация и developer API Apple;
- внешний anisette v3: **https://ani.iloader.app** (сервис upstream iloader).
  Ему передаются anisette provisioning blobs/идентификаторы по протоколу upstream.
  Нельзя представлять этот путь как «полностью офлайн» или «только серверы Apple».

TLS-проверки не отключаются. Действующие системные proxy-настройки могут влиять на
upstream HTTP-клиент. Используйте доверенную систему/сеть и изучите upstream перед
вводом аккаунта. Собственный anisette-provider и смена endpoint в UI пока не реализованы.

Пароль/2FA не записываются в localStorage, git, argv, журнал, отчёт или CI. Передача
идёт через локальный Tauri IPC в память Rust; оригинальная строка пароля обёрнута в
Zeroizing. **Полная очистка всех копий в JavaScript, allocator и upstream не гарантируется.**
Никакой tracing-subscriber для сетевых debug-логов приложение не устанавливает.
Пользовательские ошибки — закрытые коды, не сырые ответы Apple.

Сертификат с закрытым ключом и anisette-state сохраняются через системный keyring:

- `org.meganugget.signing.certificates`;
- `org.meganugget.signing.anisette`.

На Linux нужен работающий Secret Service (например GNOME Keyring) и session D-Bus.
При ошибке keyring не используется plaintext fallback. Удалять эти записи следует
через менеджер системных ключей; отсутствие локального ключа не отзывает сертификат Apple.
Подписанный IPA в памяти приложения хранится во временном файле, export — только
через Save dialog. Профиль внутри содержит персональные device provisioning данные;
**не публикуйте подписанный IPA**, не прикладывайте его к issue.

## Проверки и границы

До сети повторно читается устройство; сравнивается MinimumOSVersion. ZIP заранее
проверяется и извлекается в приватный tempdir с ограничением размера и запретом symlinks,
traversal и дубликатов. Upstream получает `.app`, а не сам распаковывает недоверенный IPA.
После подписи архив заново проходит строгую проверку installer; наличие signing artifacts
всё ещё не является независимой криптографической валидацией или подтверждением запуска.

2FA/выбор Team ожидают до 180 секунд; операция ограничена 600 секундами. При прерывании
состояние аккаунта неизвестно. Реальная авторизация, бесплатный аккаунт, подпись и установка
на физический iPhone не проверены без участия пользователя. Тесты локальных состояний
и успешная компиляция не заменяют этот аппаратный/сетевой тест.
