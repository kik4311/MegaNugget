# Архитектура

```text
Desktop WebView (локальные HTML / CSS / TypeScript)
   │ 5 типизированных IPC-команд
   ▼
Tauri host (Rust, права обычного пользователя)
   ├─ compatibility — чистая классификация, не выбор exploit
   ├─ diagnostics — ограниченный журнал закрытых кодов
   ├─ device-manager — subprocess Runner, plist, USB/lockdown
   └─ app-installer — ZIP/plist validation, snapshot, install + browse
          │ без shell, только фиксированные команды
          ▼
       libimobiledevice CLI → usbmuxd / Apple USB driver → iPhone

iOS SwiftUI → MegaNuggetCore
   ├─ DeviceInfo — UIDevice + uname
   ├─ CompatibilityManager
   ├─ SecurityResearch — пустой реестр
   ├─ JailbreakEngine — not_implemented
   ├─ Diagnostics — журнал только в памяти
   └─ RecoveryManager — инструкции, без действий
```

## Почему CLI-адаптер на первом этапе

libimobiledevice поддерживает кроссплатформенные lockdown/installation_proxy.
Запуск отдельных инструментов упрощает проверку версий и лицензий без копирования
чужого C-кода или поставки неаудированных бинарных сборок. Цена — внешние зависимости,
различия CLI и ограниченная детализация ошибок. Это не Apple-supported публичный SDK.
Протоколы Apple могут измениться. Новые версии ОС требуют отдельных тестов.

`Runner` позволяет тестировать ошибки и синтаксис без оборудования. Данные устройств
считываются из plist, а не эвристическим разбором строк. `idevice_id -l` выбирает USB,
опция `--network` не используется. Приложение не запускает `idevicepair pair`;
lockdown handshake внешней библиотеки может запрашивать стандартное доверие Apple.

## IPC и ограничения привилегий

- `scan_devices`: чтение USB и информации; проверка доступности CLI installer.
- `choose_ipa`: системный file picker; путь не приходит из WebView. Снимок в
  приватном временном файле удаляется при замене/выходе (аварийный выход может оставить файл).
- `install_ipa`: только валидный UDID, выбранный snapshot, системное Yes/No подтверждение,
  новое чтение устройства, запуск установки, проверка приложения. Возможна замена
  существующей версии и изменение app data согласно поведению iOS.
- `get_logs`: только закрытые события без пользовательских строк.
- `export_report`: системный Save dialog, только обезличенный журнал.

Нет IPC для shell, произвольного чтения файлов, скачивания, root или системных разделов.
Tauri не подключает shell/fs/network plugins. CSP запрещает удалённый контент.
Данные plist/IPA экранируются перед отображением. Не доверяйте чужим IPA.

Родительский процесс ограничивает вывод stdout/stderr 4 MiB и время команд
(10–30 секунд диагностика, до 180 секунд установка), дренирует обе трубы параллельно.
При таймауте процесс завершается; состояние устройства после прерванной установки
**неизвестно**, откат не утверждается. Исполняемые файлы берутся из `PATH` — его
содержимое и установленные CLI должны быть доверенными. Произвольные процессы,
порождённые скомпрометированным внешним инструментом, не входят в модель защиты.

Хостовые блокирующие операции вынесены в `spawn_blocking`. Состояние IPA и журнал
сериализованы mutex; во время установки другие команды могут ожидать его.
Фальшивого процентного прогресса нет; интерфейс показывает неопределённое ожидание.

## Граница iOS

SwiftUI работает в стандартной песочнице, никаких дополнительных entitlements.
Нативных exploit-компонентов нет. `uname` и `UIDevice` не предоставляют прав ядра.
Будущие C/Rust-модули должны получить отдельный контракт, модель угроз, лицензию,
проверку на физическом устройстве и согласование операции пользователем.
Системные разделы, AMFI, sandbox, Secure Boot и SEP сейчас не изменяются.
