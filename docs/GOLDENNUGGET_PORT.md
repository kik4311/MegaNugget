# GoldenNugget Mobile → MegaNugget: перенос iOS 15–17

Дата: 2026-11-06. **Частичный перенос кода, не готовый перенос всех возможностей.**

## Происхождение и авторство

Это производная часть [GoldenNugget Mobile](https://github.com/GoldenNugget-Team/GoldenNugget-mobile)
авторства **awesomenull-dev и участников GoldenNugget Team**. Полный исходный README
с неизменённым Credits сохранён в `LICENSES/GoldenNuggetMobile-README.upstream.md`.
Брендинг и графические ресурсы GoldenNugget не используются.

Закреплённая ревизия: `e4be86f050f4980ccc58de3b74f9de58b070b705`.
Импортированы `TweakCatalog.swift`, `TweakCatalogDaemons.swift`, `TweakModel.swift`,
`TweakDomainMap.swift`, `TweakCompiler.swift` из `Nugget/Core`.
Оригинальный `LICENSE` (AGPL-3.0) без изменений сохранён отдельно. В `FORKING.md`
upstream написано GPLv3 — это расхождение не используется для перелицензирования.
Исходный FORKING также сохранён. В каждом импортированном Swift-файле указаны
происхождение, дата изменений и ссылка на полные notices.

Повторяемый импорт из чистого checkout с указанной ревизией:

```sh
python3 scripts/import_goldennugget_core.py /path/to/GoldenNugget-mobile
```

`LICENSES/GoldenNuggetMobile-import.json` хранит хэши входных и выходных файлов.
Тесты проверяют их согласованность. Генератор откажет для другой/грязной ревизии.

## Что действительно перенесено

- Все **258 определений реестра** и отдельные группы служб/ScreenTime: ID, типы,
  значения, пути, ключи, ограничения и предупреждения — не выдуманный список.
- Типы scalar plist, живой выбор, валидация зависимостей/взаимоисключений.
- Соответствие путей backup-доменам и компилятор объединённых plist.
- Новый адаптер `LegacyTweakPort` и вкладка «Твики»: поиск, причины блокировки,
  редактор Bool/Int/Double/String и **локальный XML-черновик**.

## Rust-порт для Desktop (`crates/customization`)

Та же модель и компилятор, что и в Swift-адаптере, в host-крейте для Desktop:

- `catalog.json` — **снепшот 258 закреплённых upstream-спецификаций**, сгенерированный
  `scripts/export_desktop_catalog.py` из импортированного `TweakCatalog.swift`
  (репозиторий, ревизия и SHA-256 исходника внутри файла). Проверка свежести:
  `scripts/export_desktop_catalog.py --check`, запускается в Python-тестах.
- Строгие версии (1–3 ASCII-числа), пять таблиц моделей/OS, capability-гейты
  и те же статусы от `DraftCandidate` до `MechanismNotPorted`. `deviceStatus`
  из Swift портирован дословно; неверные данные устройства отвергаются.
- Компилятор (`compiler.rs`) повторяет правила Swift-порта: только явно выбранные
  спецификации; отдельные plist-предложения без слияния с устройством; offValue /
  reversible / wholeDict-ветки; путь в backup-домен по 8 правилам; зеркало
  `.GlobalPreferences` в HomeDomain; пустые словари и непокрытые пути отвергают
  весь черновик (`EMPTY`/`not mapped` не тихо отбрасываются).
- Экономика черновиков: ≤ 64 пунктов, текст ≤ 1024 байта UTF-8 без NUL,
  конфликты RTL/LTR, exclusiveWith/requires, валидация OptionalBundle, типы int/double
  из реестра без приведения.
- IPC Desktop (`apps/desktop/src-tauri/src/drafts.rs`): `tweaks_catalog` и
  `tweaks_preview`. Ошибки — стабильные snake_case-коды (`tweaks_empty_selection`,
  `tweaks_too_many_selections`, `tweaks_unknown_tweak`, `tweaks_blocked_tweak`,
  `tweaks_invalid_value`, `tweaks_conflict`, `tweaks_compile_failed`); RU/EN-тексты
  живут на клиенте. Успешная компиляция пишет событие `DraftCompiled` в журнал.
- Страница «Твики · черновики» на Desktop: цель (модель/версия iOS или подключённое
  устройство), карточки статусов, поиск/фильтр «только кандидаты», inline-редактор,
  список черновика и XML-предпросмотр. `applied_to_device` всегда `false` — и в типе,
  и в тестах, и в UI-формулировках. При смене цели каталог перезагружается, а пункты,
  переставшие быть кандидатами, удаляются из черновика, а не блокируют компиляцию
  поздним отказом.
- Тесты Rust зеркалят Swift `LegacyTweakPortTests` (3 unit + 9 integration), так что
  host и iOS-адаптер остаются поведенчески одинаковыми.

У 223 записей минимальная версия — 17.4/26/27; у 33 нижняя граница не указана.
**`nil` в minVersion не означает поддержку iOS 15.** После дополнительных
ограничений число кандидатов может быть меньше; это не количество рабочих твиков.

## Адаптация под старые версии

1. Оставлен deployment target 15.0; SwiftUI использует API, доступные с iOS 15.
2. Upstream-модель и компилятор Foundation-only собираются внутри MegaNuggetCore:
   нет зависимости от SwiftUI 26, Minimuxer, EMProxy, Airlift или NeoSpring.
3. Версии разбираются строго: 1–3 ASCII-числа, без суффиксов, пробелов и пустых
   частей. Пустая/неверная версия блокирует подбор, не включает весь каталог.
4. Диапазон адаптера — только major 15, 16, 17. Права на preview отделены от
   применения. Проверяются известная модель iPhone, её возможная OS и возможности
   оборудования: iPhone 7 не принимается за устройство на iOS 16/17, Dynamic Island
   не предлагается моделям без неё. iPad пока не включён в аппаратную таблицу.
5. Сохранены исходные min/max и hardware gates. Нет переключателя обхода ограничений
   через UserDefaults «включить непроверенные твики» в пути адаптера.
6. Компилятор принимает **только явно выбранные spec**: не генерирует все выключенные
   reversible-твики из каталога. Неизвестные, заблокированные и неверные значения
   отвергают весь черновик, а не дают тихий частичный успех.
7. Отдельные механизмы, daemon/ScreenTime nullify и opaque Siri archives
   остаются недоступны в адаптере; перенос списка не включает их применение.

## Чего эта версия НЕ делает

- Нет pairing, защитного backup, восстановления manifest и записи на устройство.
- Нет реальной замены status bar, системных обоев/PosterBoard и управления службами.
- Нет подтверждения работы ключей на каждом minor/build iOS 15–17.
- Нет загрузки внешних payload, эксплойтов или jailbreak.

XML в предпросмотре — **новый словарь предложенных ключей**, не слияние с данными
устройства. Он может содержать upstream mirror `.GlobalPreferences`, но не является
полной безопасной заменой существующего файла. Не восстанавливайте его напрямую:
он может затереть чужие ключи. Файлы не экспортируются/не передаются в restore.
Удаление из черновика только убирает локальный выбор, не «откатывает твик на iPhone».
Черновик не сохраняется после выхода из приложения.

## Следующий этап реального применения

Отдельный проверяемый канал backup/restore: read-only pairing и сведения о протоколе,
защитная копия с подтверждением, слияние с оригинальными plist, различия владельцев/
доменов для каждой версии, восстановление, проверка эффекта и безопасный rollback.
Для iOS 16 и 17 нужны реальные устройства (не iPhone 7) и тесты на точных сборках.
До этих проверок статус `draftCandidate` нельзя менять на «поддерживается/применено».

## Проверки

Добавлены 8 Swift-тестов: каталог, строгие версии, диапазон/оборудование,
новые API, типы/экранирование plist, слияние только выбранных ключей, конфликты,
числовые/текстовые ограничения, отсутствие реального применения и посторонних defaults.
Они выполняются в macOS CI: run `42234299147` (коммит `d9e9d3c`) прошёл все 5 jobs,
включая ios (`swift test` + сборки SwiftUI) за 5m53s. Это проверка компиляции и
unit-тестов, не работа твиков на устройстве. Python-тесты проверяют
происхождение и целостность импортированных файлов, включая свежесть
`crates/customization/catalog.json`, но не заменяют компиляцию Swift.
Rust-порт проверен локально: `cargo fmt --all --check`, `cargo clippy --workspace
--all-targets -- -D warnings`, `cargo test --workspace` — без ошибок (12 тестов крейта
`customization`). Дополнено: страница Desktop проверена в реальном GTK-окне (debug-сборка, X11):
каталог пришёл по IPC, редактор тумблера сохранил `SBHideLowPowerAlerts = true`
в черновик (1/64), компиляция построила XML plist с `<key>…</key><true/>`,
журнал записал `draft_compiled`. Это локальный цикл страницы, не применение
на устройстве. Аппаратная валидация iOS 15–17 по-прежнему не выполнена.
