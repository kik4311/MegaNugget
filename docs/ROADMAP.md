# Следующий этап

1. Физическая валидация iPhone9,1 и iPhone9,3: точные ProductVersion/BuildVersion,
   USB-транспорт, locked/unlocked/trusted/untrusted, отключение кабеля, журнал.
   Записать доказательства без персональных идентификаторов.
2. Подписанная собственная сборка iOS: Xcode Run и законный экспорт IPA, истёкший
   профиль, неподходящий UDID, invalid signature, upgrade с данными приложения.
3. Проверить native Desktop на Windows x64, Linux x86_64, macOS Intel/ARM;
   проверить обе версии CLI на оборудовании. Подготовить подписанные дистрибутивы
   и полный SBOM/лицензионные notices до публикации бинарников.
4. Добавить структурированные ошибки libimobiledevice через отдельный адаптер;
   native streaming progress вместо одного неопределённого ожидания.
5. Изолировать обработку недоверенных IPA, добавить fuzz-тесты ZIP/plist,
   анализ Mach-O и криптографическую проверку profile/signature где применимо.
6. Исследование доступных методов — только на разрешённых устройствах, с
   воспроизводимыми заметками, лицензионным аудитом и документированной границей
   каждой привилегии. До доказательства цепочки реестр методов остаётся пустым.
7. Отдельно проектировать rootless-bootstrap и recovery-процедуры. Не добавлять
   системные изменения под видом диагностики. Поддержка iOS 16/17 — только после
   подтверждения на конкретных моделях/сборках, не одним широким диапазоном.

Критерий допуска метода: воспроизводимые тесты на целевой сборке, разрешённые
лицензии, описание рисков/отказов/восстановления, review и явное подтверждение
пользователя. Совпадение модели само по себе недостаточно.
