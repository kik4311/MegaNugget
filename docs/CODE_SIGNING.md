# Подпись и IPA

В режиме готового подписанного IPA `ideviceinstaller` передаёт приложение
штатной службе установки устройства, которая может отказать.

Добавлен отдельный **экспериментальный** режим Apple Account: для собственного
MegaNugget backend isideload может авторизоваться, получить сертификат/provisioning
и создать подписанный IPA. Согласие, границы, хранение и непроверенные сценарии
описаны в [APPLE_SIGNING.md](APPLE_SIGNING.md). Этот путь не использует обходы Apple.
Авторизация/подпись с реальным Apple Account пока не проверены.

## Получение приложения

1. На macOS с Xcode сгенерируйте проект по DEVELOPMENT.md.
2. Назначьте свою Team и разрешённый уникальный Bundle ID; при изменении Bundle ID
   исправляйте `project.yml`, не только генерируемый проект.
3. Для проверки на своём устройстве предпочтителен Xcode Run.
4. При наличии подходящей учётной записи/профиля создайте Archive и экспортируйте
   IPA методом Development/Ad Hoc или другим разрешённым Apple способом.
   Устройство должно быть включено в профиль, если метод этого требует.
5. На Desktop проверьте USB, выберите подписанный IPA в App Installer, проверьте
   показанный Bundle ID/build и выбранный iPhone. Подтвердите системный диалог.

Personal Team и бесплатное provisioning имеют ограничения по срокам, числу устройств
и способам экспорта. Нельзя обещать универсальный IPA из любой сборки Xcode.
App Store/зашифрованные IPA, enterprise-distribution вне разрешений и произвольные
неподписанные приложения не являются поддерживаемым сценарием.

## Что проверяет Desktop

- Расширение `.ipa`, обычный файл, снимок не более 256 MiB.
- ZIP: до 20 000 записей, заявленный суммарный распакованный размер до 1 GiB.
- Запрет path traversal, дубликатов, symlinks, обратных слэшей и двоеточий в путях.
- Ровно одна корневая `Payload/*.app`, plist до 1 MiB (XML/binary).
- Bundle ID, build, executable, package type `APPL`, платформа `iPhoneOS`.
- Непустые executable, CodeResources, embedded.mobileprovision.

Это **проверка структуры**, не криптографическая проверка подписи, Mach-O архитектур,
entitlements, Team ID, UDID, даты истечения и совместимости MinimumOSVersion.
Заведомо неподходящий по версии файл пока может дойти до iOS и получить отказ.
ZIP не распаковывается. Наличие CodeResources само по себе ничего не доказывает.
Все IPA следует считать недоверенными; сторонний installer также обрабатывает архив.

## Доступность и результат

Desktop распознаёт legacy `-i/-l -o xml` и modern `install/list --xml` по `--help`.
Неизвестный CLI запрещает установку. Перед отправкой заново проверяется доступ к устройству.
Apple installation_proxy — не публичный Apple application API; протокол используется
через libimobiledevice, и работа на всех платформах/прошивках не гарантирована.

Успех показывается только после нулевого exit code **и** совпадения Bundle ID/build
в plist списка пользовательских приложений. Если такая версия уже была установлена,
проверка доказывает только её наличие, а не то, что содержимое заменилось.
Криптографический hash установленного бинарника и запуск не проверяются.

Ошибка/таймаут **не доказывает откат**: приложение могло уже установиться.
Проверьте Home Screen и Xcode перед повтором. Повторная установка может затронуть
данные приложения; не устанавливайте поверх важных приложений без резервной копии.
Автоматического удаления/восстановления нет.
