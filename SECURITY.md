# Security policy

Экспериментальный Apple Account signer вводит сетевую авторизацию и создание ресурсов
аккаунта после согласия. Сертификаты/ключи хранятся в системном keyring, не в репозитории;
данные anisette передаются стороннему upstream-сервису. См. docs/APPLE_SIGNING.md.
Не публикуйте подписанный IPA: embedded profile может содержать UDID.

MegaNugget 0.1.0 — исследовательский preview, не средство защиты. С 0.2.0 платформа
оркеструет публичные jailbreak-компоненты (Dopamine и т.п.) **код которых остаётся
upstream**; MegaNugget отдельно не содержит и не исполняет эксплойтов, а только
верифицирует и документирует официальные артефакты. Тестируйте только собственные
устройства или с явным разрешением владельца. На iPhone 7 / iOS 15.8.8 публично
задокументированы bootloops после джейлбрейка: всегда полный бэкап, готовность
к DFU-восстановлению. Не публикуйте в issue подписанные IPA.

Не публикуйте в issue UDID, pairing records, Apple ID, сертификаты, private keys,
mobileprovision, сторонние IPA и необработанные device logs. Используйте обезличенный
экспорт Desktop; он содержит только коды событий и время.

Телеметрии и скрытого сбора секретов нет. Пароль, явно введённый для подписи,
обрабатывается в памяти; сертификат/ключ сохраняются в OS keyring после согласия.
`PATH`, CLI, выбираемые IPA и загружаемые извне jailbreak-артефакты должны быть
доверенными: обязательное проверка SHA-256 до сохранения на диск. Приложение
не имеет защиты от локального пользователя с теми же правами
или скомпрометированного `curl`/libimobiledevice. Автоматических загрузок CLI нет;
загрузки релизов идут через явное действие пользователя с лимитами и дайджистами.

Перед публикацией проекта настройте GitHub Private Vulnerability Reporting для
уязвимостей MegaNugget. Сейчас адрес приватного security-контакта не назначен:
не выдумывайте рабочий канал и не отправляйте секреты в публичные обсуждения.
Уязвимости Apple сообщайте через официальный Apple Security Research:
https://security.apple.com/
